# 3D 근접 뱀서라이크 기획서 (가제)

2026-11-23 · 김성민

칼 하나로 사방에서 몰려드는 적을 베며 최대한 오래 살아남는 3D 근접 전용 뱀서라이크를 만든다. 아래 수치는 모두 시작값이며 테스트하며 조정한다. 정해야 할 것은 3번 표에 모았다.

## 1. 기획 의도와 핵심 재미

- **기획 의도**: 뱀서라이크는 원거리 공격이 기본인 게임이 많다. 적에게 직접 다가가 칼로 베는 근접 전투만으로 긴장감과 성장의 재미를 주는 게임을 만든다.
- **핵심 재미**: 마우스 방향으로 칼을 휘둘러 적 무리를 베는 타격감, 레벨업마다 두 장 중 하나를 고르는 빌드 선택, 시간이 갈수록 거세지는 적 속에서 기록을 세우는 긴장감.
- **한 판**: 8~12분. 승리 조건 없이 죽을 때까지의 **생존 시간이 곧 점수**.
- **플랫폼**: PC(Windows), 1920×1080 고정, 이동 WASD + 시점 회전 마우스 이동 + 공격 마우스 좌클릭.

## 2. 범위

- 3D 모델로 보여 주지만 **게임플레이는 평면(XZ)에서만** 한다. 점프, 높이 차, 낙하, 락온 조준은 넣지 않는다.
- 맵은 사각형으로 제한된 한 곳. 스테이지 구분 없음.
- 이번 버전에서 안 하는 것: 칼 외 무기, 캐릭터 선택, 상점, 영구 성장, 재화, 보스 패턴, 멀티플레이, 스토리.

## 4. 게임플레이

### 플레이어

| 스탯 | 값 |
| --- | --- |
| 최대 체력 | 100 |
| 이동 속도 | 5 units/s (8방향, 대각선 정규화) |
| 젬 흡수 반경 | 1.5 units |
| 피격 후 무적 | 0.5초 (모델 깜빡임) |
| 충돌 반지름 | 0.3 units |

- 1 unit = 1m. 캐릭터 키는 약 1.6~1.8 units.
- 조작: 이동 WASD/방향키(카메라 정면 기준), 시점 회전 마우스 이동, 공격 마우스 좌클릭, 대쉬(획득 후) Space, 일시정지 ESC.
- 캐릭터는 평소에 이동 방향을 바라보고, 칼을 휘두를 때는 **카메라 정면 방향**으로 몸을 돌린다(Y축 회전).
- 적과 닿으면 접촉 피해를 받고 무적이 적용된다. 구석에 몰리는 것도 난이도의 일부다.

### 칼 공격

| 항목 | 값 |
| --- | --- |
| 방향 | 플레이어 → 카메라가 바라보는 방향(화면 중앙 조준점)을 바닥(XZ)에 투영한 방향 |
| 범위 | 반지름 1.8 units, 180° 부채꼴 (XZ 평면). 적 몸통이 걸치면 맞는다 |
| 피해 / 넉백 | 10 / 0.3 units |
| 공격 딜레이 | 1초. 클릭 1회 = 1스윙, 홀드 연사 없음, 딜레이 중 클릭은 무시 |
| 타격 판정 | 휘두르는 0.3초 동안 매 프레임 범위 조회. 한 스윙당 적당 1회. 범위는 휘두른 순간의 위치에 고정 |

- 칼을 상시로 들고, 화면 중앙에 조준점을 표시해 공격 방향을 미리 보여 준다.
- 플레이 중에는 마우스 커서를 숨기고 화면 가운데에 고정한다. 레벨업·일시정지·게임 오버 팝업에서만 커서를 풀어 클릭할 수 있게 하고, 그때의 클릭은 공격으로 처리하지 않는다.
- **타격감**은 작지만 핵심이다: 칼 궤적, 적 흰색 점멸 0.1초, 히트스톱 0.03초(스윙당 첫 타격 1회), 피해 숫자 팝업, 처치 시 작은 파티클, 약한 카메라 흔들림.

### 적 3종 (전부 몸통 박치기 근접)

| | 체력 | 이동 속도 | 접촉 피해 | 경험치 | 스폰 간격 | 등장 시간 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 10 | 1.5 | 5 | 1 | 0.5초 | 0:00~ |
| B | 30 | 2.0 | 8 | 1 | 0.7초 | 1:00~ |
| C | 80 | 2.5 | 12 | 1 | 1.0초 | 3:00~ |

- 스폰 포인트는 맵 안쪽 가장자리에 8개(모서리 4 + 각 변 중앙 4). 씬 오브젝트 목록으로 관리해 나중에 추가·삭제·이동할 수 있게 한다.
- 종류별 **독립 타이머**. 자기 등장 구간일 때만, **카메라 화면 안에 들어온 포인트는 제외**하고 랜덤 1곳에 1마리를 생성한다.
- 동시 존재 최대 300마리. 오브젝트 풀링 필수. 적끼리는 충돌시키지 않고 플레이어와의 접촉만 판정한다.

### 난이도 곡선

한번 등장한 적은 사라지지 않고 페이즈마다 종류가 누적된다. 수치는 ScriptableObject로 분리해 코드 수정 없이 튜닝한다.

| 구간 | 등장 | 체력 배율 |
| --- | --- | --- |
| 0:00–1:00 | A | ×1.0 |
| 1:00–3:00 | A, B | ×1.2 |
| 3:00–6:00 | A, B, C | ×1.5 |
| 6:00~ | A, B, C | ×2.0에서 시작, 매분 +15% |

### 레벨업

- 레벨 **0에서 시작, 최대 10**. 레벨업과 선택은 정확히 10번.
- 필요 경험치 = `5 + 4 × 현재 레벨` (0→1은 5, 9→10은 41, 총 230). 젬은 A·B·C 모두 경험치 1이고, 체력 회복 아이템은 없다.
- 레벨업 시 게임이 멈추고 무작위 **2장 중 1장**을 고른다(클릭 또는 키 `1`/`2`). 두 장은 서로 다르다.
- 이미 가진 스킬이 뜨면 새로 얻는 대신 **그 스킬을 강화**한다. 3단계까지 올린 항목은 선택지에서 제외.
- 레벨 10 이후에도 젬은 흡수되지만 레벨업은 없다. 경험치 바에 `MAX`를 표시한다.
- 항목 8개 × 3단계 = 24단계인데 선택은 10번뿐이다. **무엇을 고르느냐가 빌드 차이**다.

### 스킬 4종 (획득이 1단계, 최대 3단계)

| 스킬 | 1단계 (획득) | 단계마다 | 3단계 |
| --- | --- | --- | --- |
| 대쉬 | Space. 이동 방향(정지 중이면 카메라 정면)으로 3 units 돌진. 쿨타임 8초 | 쿨타임 −2초 | 4초 |
| 검기 날리기 | 칼을 **5번째** 휘두를 때마다 조준 방향(카메라 정면)으로 검기 1개. 피해 칼의 50%, 적 관통, 사거리 9 units | 개수 +1 (30° 간격 부채꼴) | 3개 |
| 회전 베기 | 칼을 **3번째** 휘두를 때마다 주변 360° 베기. 피해 칼의 80%, 반지름 2 units | 반지름 +0.5 | 3 units |
| 냉기 속성 부여 | 기본 공격에 맞은 적이 30% 확률로 3초 빙결(정지·접촉 피해 없음, 넉백은 받음). 칼 궤적이 푸르게 바뀌고 얼음 결정이 흩날린다 | 확률 +10% | 50% |

- 검기·회전 베기의 스윙 카운트는 **획득한 순간부터** 센다. 검기·회전 베기 타격에는 냉기가 적용되지 않는다.

### 능력치 4종 (최대 3단계)

| 능력치 | 1단계당 | 3단계 |
| --- | --- | --- |
| 이동 속도 | +10% | +30% (5 → 6.5 units/s) |
| 체력 | 최대 체력 +20 (올린 만큼 즉시 회복) | +60 (100 → 160) |
| 공격 속도 | 공격 딜레이 −10% | −30% (1초 → 0.7초) |
| 공격력 | 칼 피해 +20% (검기·회전 베기 포함) | +60% |

- 공격 속도가 오르면 스윙 횟수가 늘어 **검기·회전 베기 발동도 같이 빨라진다**(의도된 시너지).

### UI / 기록

- 화면 3개: 타이틀 / 인게임 / 게임 오버. 레벨업 선택창과 일시정지는 인게임 위에 겹치는 팝업.
- 타이틀: 제목, 시작, 종료, 최고 기록(생존 시간·처치 수).
- HUD: 좌상단 체력 바 / 상단 전체 폭 경험치 바 + 레벨 / 상단 중앙 생존 시간 `mm:ss` / 우상단 처치 수 / 하단 보유 스킬·능력치 아이콘과 레벨.
- 레벨업 팝업: 카드 2장. 카드에 이름, 아이콘, 신규는 `NEW`, 강화는 `현재 단계 → 다음 단계`, 한 줄 설명.
- 일시정지(ESC): 계속하기 / 타이틀로. 게임 오버: 생존 시간, 처치 수, 도달 레벨, 신기록이면 `NEW RECORD`, 다시 하기 / 타이틀로.
- 기록은 `PlayerPrefs`에 저장(서버·랭킹 없음): 최고 생존 시간, 최다 처치 수, 최고 레벨. 게임 오버 직후 이전 기록보다 클 때만 갱신한다.

## 5. 카메라·조준·맵·연출

### 카메라 (3인칭 추적, 시작값)

| 항목 | 시작값 | 비고 |
| --- | --- | --- |
| 투영 | Perspective, FOV 70° | 뒤·옆이 넓게 보이도록 넓게 잡음. 튜닝 대상 |
| 위치 | 플레이어 뒤 약 7 units, 어깨 높이 위 약 2.5 units | 피봇(중심점)은 플레이어 상체 높이 |
| 좌우 회전 | 마우스 X로 360° 자유 회전 | 카메라가 플레이어 주위를 동그라미로 돈다 |
| 상하 각도 | 마우스 Y로 5°~60°, 시작 25° | 너무 낮거나 수직이 되지 않게 제한 |
| 추종 | 피봇이 플레이어를 부드럽게 따라가고, 회전은 즉시 반영 | 조작 지연을 느끼지 않게 |
| 충돌 보정 | 벽·소품에 가려지면 카메라를 플레이어 쪽으로 당긴다 | 맵 가장자리에서 특히 중요 |
| 감도 | 설정에서 조절, 상하 반전 옵션 | |

- 이동은 카메라 정면 기준 WASD(카메라가 도는 방향이 곧 앞).
- 해상도는 1920×1080 고정.

### 조준

1. 화면 중앙에 작은 조준점을 둔다.
2. 카메라 정면 방향을 바닥 평면(XZ)에 투영한 방향이 공격·검기·대쉬(정지 시)의 방향이다. 카메라가 위아래를 향해도 높이는 무시한다.
3. 칼을 휘두르는 순간 캐릭터가 그 방향으로 몸을 돌리고, 부채꼴 범위는 휘두른 순간의 위치와 방향에 고정된다.

### 맵

- 직사각형 제한 맵, 시작 크기 **40 × 24 units**, 원점 중심(x ∈ [-20, 20], z ∈ [-12, 12]). 카메라가 어느 방향을 봐도 맵이 너무 넓지 않게 테스트하며 조정한다.
- 경계는 **물리 벽이 아니라 코드 Clamp**(XZ)로 처리해, 적 300마리가 몰려도 물리 비용을 쓰지 않는다.
- 3인칭 카메라는 가장자리에서 맵 밖을 비출 수 있어, 경계에 **눈에 보이는 높은 벽**을 세우고 바깥은 안개로 가린다. 카메라 위치도 벽 안쪽으로 제한한다.
- 플레이어와 적 모두 경계 밖으로 나갈 수 없다.
- 바닥에 약한 변화(풀·돌)를 흩뿌려 이동감을 보여 준다.

### 렌더링·연출

- URP 3D, 방향광 1개 + 부드러운 그림자(가까운 거리만). Bloom은 얼음·검기 이펙트에만 약하게.
- 칼 궤적: TrailRenderer 또는 VFX Graph의 반달형 슬래시.
- 냉기: 칼 궤적이 푸른색, 빙결된 적은 푸른 틴트 + 얼음 결정 파티클.
- 피해 숫자는 월드 공간 TMP를 카메라를 향하게(Billboard) 풀링해서 쓴다.
- 사운드: 스윙, 타격, 레벨업, 피격, 사망.

## 6. 기술 구조

- Unity 6, URP 3D 템플릿, Input System. Windows 빌드, 1920×1080 고정.
- 수치는 코드에 직접 쓰지 않고 ScriptableObject 또는 Inspector 노출 필드로 분리해, 테스트하며 조정할 수 있게 한다.
- 플레이 중 `Instantiate`/`Destroy` 금지. 적·젬·검기·피해 숫자는 오브젝트 풀링.
- `Time.timeScale`은 `GameManager`에서만 변경한다.
- 적 이동은 NavMesh 없이 플레이어를 향한 직접 추적. 맵이 장애물 없는 빈 평면이라 충분하다.

| 스크립트 | 역할 |
| --- | --- |
| `GameManager` | 게임 상태(진행·일시정지·오버), 생존 시간, 처치 수 |
| `PlayerController` | 카메라 기준 WASD 이동, 맵 경계 제한, 공격 시 카메라 정면으로 회전, 애니메이션 파라미터 |
| `CameraRig` | 마우스 시점 회전, 카메라 충돌 보정, 조준 방향(카메라 정면의 XZ 투영) 계산 |
| `PlayerHealth` | 체력, 피격, 무적 시간, 사망 이벤트 |
| `SwordAttack` | 클릭 입력, 딜레이, XZ 부채꼴 판정, 스윙 횟수 카운트 |
| `Enemy` | 추적 이동, 피격·넉백·빙결·사망, 젬 드롭 |
| `EnemySpawner` | 종류별 타이머, 화면 밖 스폰 포인트 선택(`WorldToViewportPoint`), 풀 사용 |
| `ExpGem` / `ExperienceManager` | 젬 흡수, 경험치 계산, 레벨업 이벤트 |
| `AbilityData` (SO) | 스킬·능력치 이름, 아이콘, 단계별 수치 |
| `UpgradeManager` | 레벨업 시 무작위 2개 추첨, 선택 반영, 최대 레벨 10 제한 |
| `PlayerSkills` + `DashSkill` / `SwordWaveSkill` / `SpinSlashSkill` / `FrostSkill` | 보유·단계 관리 + 개별 스킬 |
| `MapBounds` | 맵 사각형(XZ) 관리, `Clamp` |
| `CameraFollow` | 3인칭 추종(마우스 회전) + 벽 충돌 보정 + 맵 안쪽 클램프 |
| `CombatEffects` | 히트스톱, 피해 숫자, 처치 파티클 |
| `UIManager` / `SaveManager` | HUD, 팝업 / 최고 기록 저장 |

- 적끼리 밀어내지 않으면 플레이어 주변에 적이 작은 고리로 겹쳐 보일 수 있다. 플레이테스트 후 약한 분리(separation) 추가 여부를 결정한다.

## 7. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| **적 300마리에서 60fps** (가장 큰 위험) | 적 모델 500 삼각형 이하, 머티리얼 공유 + SRP Batcher/GPU 인스턴싱, 먼 적의 애니메이션 컬링, 그림자는 플레이어 근처만. 초기에 300마리 부하 테스트를 먼저 한다 |
| **뒤·옆에서 오는 적을 못 봐서 억울하게 죽음** (3인칭 화면의 한계) | 화면 가장자리 방향 표시, 시야각(FOV 70°) 넓게, 스폰 위치와 속도 조절, 회전 베기(360°)의 가치 |
| 마우스 시점 회전이 불편하거나 멀미 | 감도·반전 옵션, 회전 부드럽게, 카메라 흔들림은 약하게·끌 수 있게 |
| 화면 중앙 기준 조준이 어렵다 | 칼 범위를 넓게(180°) 유지, 조준점 표시. 필요하면 약한 자동 보정 검토 |
| 벽·소품에 카메라가 가려짐 | 카메라 충돌 보정, 큰 소품은 맵 가장자리 바깥에만 배치 |
| 에셋 통일감 | 한 팩에서 캐릭터·적·소품을 모두 고른다. 다른 팩과 섞으면 어색해진다 |
| 애니메이션 부족 | 캐릭터는 Idle/Run/Swing 필수. 적은 Run만으로 시작 가능 |
| 범위 확장 | 높이·보스는 이번 버전에서 하지 않는다(점프·슬라이드는 3번 표에서 결정) |

## 8. 필요한 에셋

- 플레이어 모델(리깅, Idle/Run/Swing/Dash/Hit/Death 애니메이션) + 칼.
- 적 3종 모델(Run, Hit/Death).
- 바닥 타일 또는 텍스처, 경계 울타리, 소품 약간.
- 이펙트 텍스처·메시(슬래시, 타격 스파크, 얼음 결정), 젬 모델.
- 사운드 전부, UI 아이콘 8종(스킬 4 + 능력치 4).
- 후보 출처: CC0나 상업 이용이 가능한 로우폴리 팩(예: Kenney, Quaternius). **라이선스는 받을 때 직접 확인**하고 출처 표기를 남긴다.
